# Domain Knowledge Hub — управління знаннями культурної спадщини

Репозиторій знань до курсу «Сховища знань та управління знаннями» (ЛНУ ім. Івана Франка, ФеІ-42).
Тематична область (варіант 24): **управління знаннями про об'єкти культурної спадщини** —
облік пам'яток і музейних предметів, умови зберігання, реставрація, атрибуція.

Виконав: Чапля Олег, група ФеІ-42. Перевірив: ас. Керод Т. І.

## Структура

```
docs/        постановка проблеми, схеми, реєстри, звіти за результатами
prompts/     версіоновані підказки до LLM (роль, контекст, завдання, формат, правила)
llm_log/     журнал взаємодії з моделями: метадані, сирий вихід, розібраний JSON
claims/      таблиця тверджень і їх верифікації
schemas/     Pydantic-схеми структурованого виходу моделей
models/      словник, правила, фрейми, таксономія (ЛР 3–5)
engine/      рушій прямого ланцюжкування (ЛР 4)
kb/          документи знань у форматі docs-as-code (ЛР 2)
tools/       допоміжні скрипти: журналювання, валідація, лінтер метаданих, метрики
tests/       pytest: золотий набір правил, перевірки таксономії
```

## Запуск з нуля

```bash
python -V                      # 3.12.x (перевірено на 3.12)
pip install -r requirements.txt
python tools/validate_claims.py llm_log/session_01.jsonl   # валідація виходу моделі
python tools/lint_meta.py kb/ --max-age-days 365           # лінтер метаданих (ЛР 2)
pytest tests/ -v                                           # 38 тестів (ЛР 4 і ЛР 5)
```

Відтворення ЛР 5 з нуля, у цьому порядку:

```bash
python tools/build_terms.py          # корпус термінів -> models/terms.csv (150 термінів)
python tools/build_taxonomies.py     # експертна версія і кластеризація (seed=42)
python tools/build_final_taxonomy.py # підсумкова таксономія -> models/taxonomy_final.csv
python tools/merge_llm_findings.py   # перенесення 23 термінів і поділу документів із LLM-чернетки
python tools/fill_definitions.py     # визначення для кожного вузла (182 з 182)
python tools/export_skos.py          # SKOS -> models/taxonomy.ttl (1240 тріплетів)
python tools/taxonomy_metrics.py     # метрики -> tmp/taxonomy_metrics.json
pytest tests/test_taxonomy.py -v     # 14 перевірок таксономії
```

Кластеризація детермінована: `random_state=42` у `TruncatedSVD`, `AgglomerativeClustering`
із `linkage="ward"` випадковості не має. Версії бібліотек зафіксовано в `requirements.txt`.

Відтворюваність: усі скрипти детерміновані; там, де використовується випадковість
(кластеризація в ЛР 5), seed фіксується в коді й зазначається у звіті. Виходи мовних моделей
не відтворювані точно — тому сирий вихід кожної сесії зберігається в `llm_log/`.

## Моделі, використані як експерти

| Роль | Модель | Призначення |
|---|---|---|
| A | Claude Opus 5 (`claude-opus-5`) | основна експертна сесія, генерація тверджень |
| B | Claude Haiku 4.5 (`claude-haiku-4-5-20251001`) | незалежна перевірка тверджень (V3), обчислення κ |

Відхилення від умови: завдання передбачає моделі різних постачальників. Тут використано дві
різні за розміром моделі одного постачальника, бо доступу до API інших провайдерів немає.
Це зафіксовано у звітах і впливає на інтерпретацію κ: узгодженість моделей однієї родини
очікувано вища, ніж у незалежних постачальників.


## Правила нормалізації термінів (ЛР 5)

Корпус термінів (`models/terms.csv`) будується скриптом `tools/build_terms.py` за такими правилами:

1. **Регістр.** Нижній регістр, крім абревіатур, які лишаються у верхньому: RH, CIDOC CRM, SKOS,
   AAT, OWL, RDF, ADR, ISO, LOD, ICOM, ICCROM, CCI, UUID, SPARQL, MQTT, OCR, LLM, CoVe, KMS,
   MECE, TF-IDF, ARI.
2. **Форма.** Однина, називний відмінок для канонічної назви.
3. **Символи.** Апостроф уніфіковано до U+02BC (`ʼ`), різновиди дефіса — до звичайного `-`,
   послідовності пробілів згортаються в один.
4. **Синоніми.** Синонім ніколи не стає окремим терміном: він потрапляє в колонку `alt_labels`
   канонічного терміна.
5. **Відсів.** Терміни коротші за три символи відкидаються.
6. **Частота.** Рахується за основою першого слова (перші шість символів), щоб словоформи
   «пам'ятка», «пам'ятки», «пам'яток» зараховувалися одному терміну. Це груба, але передбачувана
   заміна лематизації: словника української морфології в проєкті немає.

Джерело корпусу — реальні документи репозиторію: `kb/*.md`, `docs/*.md`, `sources/*.md`,
`models/rules.json`, `claims/claims.csv`, `models/glossary.json`.

## Безпека

Ключі API у репозиторії не зберігаються (`.env` у `.gitignore`). Персональні дані співробітників
і відвідувачів у сховище не вносяться; у документах знань фіксуються лише посади власників знань.
Числові приклади (інвентарні номери, вимірювання, статистика) — умовні, оскільки доступ до
реальної облікової системи установи відсутній; нормативні твердження спираються на публічні
джерела й верифіковані.
